# Strategy Lab 系统规则

## 基本原则

1. 优先保持最小改动，不修改无关的回测逻辑。
2. 普通代码错误可以自动修复并重新运行。
3. 如果修复会改变策略含义，先说明假设再执行。
4. 不删除或覆盖历史实验，除非用户明确授权。
5. 涉及删除、清空或重置操作，必须进行 `yes/no` 二次确认。
6. 当读完docs下的文档规则后，回复只需：加载完毕，可以开始了！
7. 当回测结束后直接输出回测结果，并询问是否我继续分析结果：是/否！
8. 我说加载规则，默认加载docs/下的所有文件并更新规则记忆！
9. Python回测层只负责计算、校验和归档客观事实，不输出策略好坏判断。
10. 回测完成后先输出结果并询问“是否进入分析阶段：是/否”；只有用户回答“是”后，才进入AI研究分析阶段。

## 路径规则

- Python 路径统一基于 `Path(__file__).resolve()` 计算。
- 原始数据位于 `shared/data/`。
- 实验位于 `shared/experiments/{research_name}/exp_XXX/`。
- `research_name` 表示研究方向/策略家族，不等同于当前默认策略；例如动量研究使用 `momentum`，均线研究使用 `moving_average`。
- 新回测若改变核心信号类型、指标体系或持仓逻辑，应先新建研究目录，不得因为当前状态中的默认策略名称而沿用旧目录。
- 若用户未明确研究目录，应根据研究主题自动命名；无法判断时，在执行回测前说明目录命名假设。

## 实验规则

- 每个研究方向独立编号，编号从该目录现有最大编号递增。
- 已完成实验原则上只读保存。
- 新实验必须保存代码快照。
- 实验结果必须包含校验报告。
- 每个新实验必须输出标准结果集：`result.csv`、`metrics.json`、`trades.csv`、`equity_curve.csv`、`validation.json`，并保留`meta.json`和策略代码快照。
- `metrics.json`、`validation.json`中的内容必须由Python计算；AI只能读取、解释和比较，不能修改统计事实。

## 买点提取规则

- 当用户要求“提取一个股票/板块/指数/ETF 看买点”，或指定具体标的查看买点时，必须基于用户指定的实验规则重新计算该标的的全部买点，不能从组合汇总结果臆测。
- 未指定标的时，从该实验结果集中的有效标的随机选择一个；已指定时必须使用指定标的，并返回其名称和代码。
- 输出至少包含：研究方向、实验编号、标的名称、标的代码、买点日期、买点触发条件和完整买点数据。
- 同时生成通达信主图公式：每个买点日期生成一个 `D#:=DATE=YYMMDD;`，合并为 `BUY_DAY`，并用 `STICKLINE` 将买点 K 线实体和影线标红。
- 通达信公式必须完整可执行：买点有多少个就完整生成多少条 `D#` 和对应的 `BUY_DAY` 条件，禁止使用省略号、`...`、“其余日期略”或任何占位文本。
- 当用户提出“看看买点”“提取买点”或同义要求时，最终回复中必须直接附上完整通达信公式；不能只在工具输出、附件或中间结果中生成，也不能用摘要代替公式。
- 最终回复中的通达信公式必须包含全部买点日期定义、完整 `BUY_DAY` 逻辑和全部 K 线标记语句，并与返回的买点数量逐一对应。
- 返回买点时，买点数量下方必须列出该结果对应的研究方向、实验编号、买入条件、卖出条件、持仓/资金假设和成本口径。
- 在卖出规则下方，必须附上该标的按同一实验规则计算的简要表现：已完成交易数、交易胜率、平均单笔收益、累计交易收益、平均持有天数和最大单笔亏损；若没有完成交易，明确标注为“暂无可计算的完整交易”。
- 买点日期必须来自实际计算结果；若无买点，明确返回“无符合条件的买点”，不得生成虚假日期。

## 当前系统边界

- 当前主要策略为 `momentum`。
- 当前回测使用本地 Python 和 pandas。
- 当前实验系统仍属于研究原型，不代表实盘可用。

# 系统文档维护与保护规则

## 一、文档修改原则

所有 docs 目录中的系统文档：

修改前必须：

1. 读取当前文件内容。

2. 理解已有规则。

3. 保留历史信息。

4. 避免覆盖已有设计。

禁止：

直接删除整个文档重新生成。

---

## 二、文档类型管理

不同文档采用不同维护方式。

### 1. 规划类文档

例如：

SYSTEM_ROADMAP.md

DEVELOPMENT_PLAN.md

维护方式：版本更新。

要求：保留历史版本信息。

### 2. 理念类文档

例如：

RESEARCH_PHILOSOPHY.md

维护方式：谨慎修改。

重大理念变化必须记录到 `DECISION_LOG.md`。

### 3. 状态类文档

例如：

CURRENT_STATUS.md

维护方式：允许更新。

要求：保留当前状态和重要历史节点。

### 4. 决策记录类文档

例如：

DECISION_LOG.md

维护方式：只允许追加。

禁止删除历史决策或覆盖已有记录。

如果出现新的设计方向，增加新的 Decision 编号。

---

## 三、代码修改前置检查

任何代码修改前必须确认：

1. 当前需求属于 `SYSTEM_ROADMAP.md` 中哪个阶段。
2. 是否符合 `RESEARCH_PHILOSOPHY.md`。
3. 是否属于 `DEVELOPMENT_PLAN.md` 当前任务。
4. 是否需要更新 `DECISION_LOG.md`。

---

## 四、系统扩展控制

新增功能必须判断：

1. 是否解决当前核心问题。
2. 是否属于当前开发阶段。
3. 是否会造成无意义复杂度。

如果不属于当前阶段，进入未来规划，禁止直接开发。

---

## 五、实验数据保护

以下内容禁止未经确认修改：

- 历史实验结果
- experiment目录
- 回测输出
- 原始数据

任何清理操作必须先确认。

## 六、永久删除规则

系统删除操作采用永久删除，不使用回收站，也不保留实验目录副本。

删除单个实验时，必须同时完成：

- 删除该实验目录及其内部的结果、元数据、验证报告和代码快照。
- 从 `shared/experiments/index.csv` 删除该实验的索引记录。
- 清理 `docs/` 中对该实验的明确路径引用。
- 删除后校验目录和索引记录均不存在。

`clear` 和 `reset` 采用同样的永久删除规则，并且仍需用户输入 `yes` 确认。

为避免破坏系统，删除功能不得自动删除 Python 源码、原始行情数据、其他研究方向实验或系统规则文档；这些内容不是被删除实验的归档副本。若未来需要处理源码中的硬编码实验引用，必须作为单独的代码变更审查，不在删除动作中隐式修改。

## 七、实验名称规则

每个实验同时具有两种标识：

- 内部标识：英文研究目录和 `exp_XXX` 编号，用于程序路径、索引和兼容历史数据。
- 中文名称：根据用户提出的研究规则生成，用于用户查看、调用和删除。

新实验不得以用户输入的中文名称直接作为目录名。查看实验时优先展示中文名称；删除实验时支持直接使用中文名称，系统再解析到唯一的内部目录。若中文名称不唯一，必须停止操作并要求使用更具体的名称，不得猜测删除。

## 八、统计维度与验证同步规则

统计结果的任何增、删、改，都必须同步修改对应的验证环节。

适用范围包括：

- 新增或删除收益指标；
- 修改 MFE、MAE、回撤、胜率或风险指标口径；
- 修改信号字段、交易字段或结果字段；
- 修改样本等级、数据不足和异常值处理规则；
- 修改交易成本、持仓和退出统计口径。

执行统计维度修改时，必须同步完成：

1. 更新标准答案或固定测试样例。
2. 增加、删除或修改对应的单元测试。
3. 更新字段契约检查，确保输出字段和验证字段一致。
4. 对受影响的统计模块执行定向测试。
5. 如果影响公共统计函数、买卖逻辑或结果结构，执行回归测试。

统计测试未通过时，不得将新的实验结果作为正式研究结果归档，也不得仅通过修改测试断言来掩盖算法变化。新增统计维度必须同时说明计算口径、数据不足处理和验证方法。
