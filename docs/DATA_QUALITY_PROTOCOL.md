# 分析数据库数据质量与外部核验流程

## 1. 质量门禁位置

数据源进入分析数据库必须经过：

```text
原始文件
  -> 结构/字段标准化
  -> 目标代码筛选
  -> 数据质量门禁
  -> Parquet 发布
  -> SQLite 来源与质量登记
```

执行入口是 `build_analysis_database.py` 的 `build` 或 `update` 模式。两个模式结束前都会自动调用 `data_quality_gate.py`。

## 2. 自动检查项目

### 可自动修复或隔离

- 删除缺失代码或交易日期的行；
- 删除开高低收全部为空的占位行；
- 删除 OHLC 违反 `high >= max(open, close, low)` 或 `low <= min(open, close, high)` 的行；
- 删除价格小于等于 0 的行；
- 对重复的 `instrument_code + trade_date` 保留最后来源记录；
- 将被隔离行写入 `quality_quarantine.parquet`，不覆盖原始数据。

### 保留但强制标记

- 只有收盘价、缺少开高低的历史行标记为 `quality_status=close_only` 和 `is_valid_ohlc=false`；不允许直接用于完整 K 线、波动率、ATR 或高低点策略。
- 成交量或成交额为 0 不自动删除。指数数据中这可能是口径或占位问题，标记为 `is_zero_volume` / `is_zero_amount`，使用成交量因子时必须另行过滤。
- 相邻交易日涨跌幅绝对值超过 30% 标记为 `large_return_flag`，不自动删除，因为历史制度变化、指数重构和真实极端行情都可能产生大幅变化。

## 4. 外部抽样核验

每次新增数据后，建议随机抽取：

- 2 个宽基指数；
- 2 个申万一级行业；
- 3 个日期，至少包含最新日期、随机历史日期和结构变更附近日期；
- 核对代码、日期、开高低收、涨跌幅和交易日存在性。

本次抽样使用 2023-01-03、2024-06-03、2025-01-02，覆盖 `000001.SH`、`000300.SH`、`801010.SI`、`801950.SI`。公开资料中，`000300.SH` 在 2025-01-02 的开高低收为 3820.3952、3934.2034、3796.3389、3934.9109，与库中完全一致；公开行业研究资料也确认 801010 为申万农林牧渔，且 2025-01-02 的行业表现记录与库中方向一致。

外部核验是抽样证据，不替代全量逻辑检查。外部服务可能存在复权、指数版本、收盘时点或四舍五入差异，差异必须先判断口径再修正。

## 5. 发布标准

- 身份、日期、价格、主键检查通过，才允许发布；
- close-only 行可以存在，但研究查询默认应使用 `is_valid_ohlc=true`；
- 质量异常必须有报告和隔离文件；
- 外部抽样核验出现代码/日期/价格系统性差异时，停止增量发布，先确认数据口径；
- 原始数据永远只读，任何修正只能发生在分析层并记录规则。
