首次建立：2026-10-17

扫描程序：`data_source_inventory.py`  
扫描报告：`shared/data/data_source_inventory.json`

## 一、用途和维护原则

本文件记录原始数据源的目录、字段、覆盖范围、质量观察和入库注意事项，供后续建设分析数据库使用。

- 原始数据只读保存，不在源目录直接改写。
- 数据入库前先经过结构标准化、质量检查和来源登记。
- 每次新增或更新数据后重新运行扫描程序，并记录扫描时间。
- 文件名、更新日期和目录位置只用于识别来源，不能单独证明数据已经连续或完整。
- 正式研究必须保存来源路径、文件版本、分类版本、处理规则和入库批次。

默认扫描命令：

```powershell
python data_source_inventory.py
```

默认模式扫描全部文件的元数据，并对每种数据类型、频率和年份选择代表 CSV 做字段和质量检查。全量逐行检查全部 CSV 时使用：

```powershell
python data_source_inventory.py --full
```

`--full` 可能需要较长时间，不应作为每次更新的默认动作。

## 三、大盘指数数据

### 3.1 分钟数据

代表文件字段：

| 原始字段 | 标准字段建议 | 类型 | 说明 |
|---|---|---|---|
| 指数代码 | `instrument_code` | 文本 | 例如 `000001.SH` |
| 指数名称 | `instrument_name` | 文本 | 例如上证综合指数 |
| 交易时间 | `trade_time` | 时间戳 | 分钟级时间 |
| 开盘价 | `open` | 数值 | 指数点位 |
| 最高价 | `high` | 数值 | 指数点位 |
| 最低价 | `low` | 数值 | 指数点位 |
| 收盘价 | `close` | 数值 | 指数点位 |
| 成交量(股) | `volume` | 数值 | 需确认指数成交量口径 |
| 成交金额（元） | `amount` | 数值 | 元，需确认是否为成分股汇总口径 |

代表文件抽查结果：

- 单日样本包含约 573 个指数代码和 559 个指数名称。
- 时间可解析，示例日期为 2026-01-05，时间范围约 09:30 至 15:30。
- OHLC 逻辑未发现错误，未发现负价格或负成交量。
- 部分指数的成交量或成交额为 0；这可能是指数没有对应成交统计，而不应直接判为行情错误。

### 3.2 日线数据

代表文件除 OHLC 外还包含涨跌幅、涨跌额、成交量和成交额等字段，示例字段包括：

```text
TS指数代码, 指数名称, 交易日期,
开盘点位, 最高点位, 最低点位, 收盘点位,
前收盘点, 涨跌点, 涨跌幅(%),
成交量(股), 成交额(千元)
```

日线数据的成交额单位与分钟数据不同：分钟文件标为“元”，日线文件标为“千元”。进入分析数据库前必须统一单位，建议统一存为元，同时保留 `source_amount_unit` 记录原始单位。

本次代表文件包含约 10,889 行、10,889 个代码，说明日线文件可能同时覆盖大量指数。具体指数覆盖必须按文件逐日校验。

## 六、当前质量结论

### 已确认的优点

- CSV 和 ZIP 目录组织有明显的年度和频率分层。
- 大盘和申万数据均提供日线与分钟线。
- 代表文件字段稳定，能够映射到统一 OHLCV 数据模型。
- 代表文件未发现字段数量错误、时间无法解析或 OHLC 逻辑错误。
- 压缩包提供历史归档，适合保留原始来源。

### 需要重点处理的问题

1. **数据单位不统一**：日线成交额是千元，分钟成交额是元；必须在入库时转换并保留原始单位。
2. **分钟记录边界不统一**：大盘代表文件出现 15:30，申万代表文件到 15:00；需确认是否包含收盘后指数记录或其他时段。
3. **零成交记录**：指数分钟数据存在系统性 `volume=0` 或 `amount=0`，不能直接用于成交量放大、流动性和 VWAP 因子。
4. **指数数量和名称不完全一致**：同一日大盘和申万文件的代码数量不同，不能按名称强行关联。
5. **代码和名称变更未登记**：长期回测必须建立代码名称历史和分类版本表。
6. **压缩包内部尚未全量逐行检查**：当前报告默认是代表文件检查；需要正式建库前运行 `--full` 或分批全量检查。
7. **来源元数据不足**：当前文件名带有整理者和日期，但还缺数据源版本、下载时间、修订时间和授权信息。

## 八、后续数据更新流程

后续新增数据时按以下顺序处理：

1. 将原始文件放入对应的“数据源/类别/频率/年份”目录，不覆盖旧文件。
2. 运行 `data_source_inventory.py` 更新结构报告。
3. 检查新增代码、字段变化、日期覆盖、分钟时段和单位。
4. 通过质量门禁后，转换为统一字段并写入分析数据库的临时区。
5. 对临时区做主键、重复、时间连续性和单位检查。
6. 通过检查后写入正式分析区，并记录 `ingest_batch`。
7. 更新本文档中的结构变化和已知问题。

当前不应直接把原始 CSV 作为策略输入。策略应读取分析数据库中经过标准化和质量登记的数据。
